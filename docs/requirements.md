# 需求与验收

## 背景与目标

将 C6C 的 SD 卡历史告警录像增量备份到阿里云盘，保留独立原片及事件时间，降低因 SD 卡循环覆盖而丢失片段的概率。主机是全天在线的 Mac mini，资源占用与维护成本优先。

## 范围

MVP 支持单摄像机、单通道、单网盘账号。每天运行一次，发现最近数天的事件记录，并处理数据库中尚未完成的片段。手动运行与定时运行使用同一入口。

支持历史事件录像查询、标准回放流落盘、上传、远端核验、失败恢复、状态查询和脱敏日志。

当前仅实现 P1 能力探测，不提供每日备份运行时。MVP 不包含云存储录像下载、RTSP 实时录制、全天录像备份、人物识别、视频合成、网页界面、菜单栏界面或多用户服务。

## 功能要求

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| F01 | 查询 SD 历史事件，区分事件与定时录像 | 用 App 中可核对的事件对照查询结果 |
| F02 | 保存已有事件片段，不产生新的摄像机录像 | 对照历史时间、画面和实际时长 |
| F03 | 同一事件重复发现不重复上传 | 连续运行两次，远端路径及记录数量不增加 |
| F04 | 跨午夜事件按天查询，保留全部分段 | 合成响应与真实样本分别验证边界 |
| F05 | 网络失败、进程中断后能恢复 | 在保存与上传阶段中断并重跑 |
| F06 | 上传成功与远端核验分别记账 | 模拟成功返回但远端文件缺失或大小错误 |
| F07 | 每天定时运行，结束后无应用常驻进程 | 检查 launchd 与进程列表 |
| F08 | 空间或时间预算不足时暂停并保留待办 | 触发预算，确认不丢记录且不误报完成 |
| F09 | 权限、固件或加密不支持时输出可定位原因 | 实机失败与固定错误响应验证 |
| F10 | 初始版本不自动清理本地或云端视频 | 检查配置默认值及故障用例 |

## 轻量化要求

- 使用 Python 3.12+；协调逻辑优先标准库，不引入服务框架。
- 任务未运行时，应用常驻进程数为 0。
- 下载并发和上传并发均为 1，默认按“保存一个 → 上传 → 核验”串行执行。
- FFmpeg 采用流复制；若必须解码转码才能工作，退出当前兼容路径，先记录原因并重新评审资源预算。
- 采用有界流式 I/O，不将整个视频或所有录像分页结果读入内存。
- 默认每次运行最多 3 小时，暂存最多 2 GiB，保留磁盘可用空间至少 5 GiB。
- 资源**设计目标**：协调进程峰值 RSS 不超过 80 MiB，整个任务相关进程峰值 RSS 合计不超过 300 MiB。尚无实测数据，需按 [测试计划](testing.md)确认，不作为现有性能声明。
- 默认不做上传后的整片回下载校验；远端哈希可用时比较哈希，否则只记为较低校验等级并保留本地文件。

## 约束与待确认事项

- C6C 名称涵盖不同硬件及固件，具体支持情况以目标设备为准。
- 开放平台授权、回放服务、流量费用和接口限制待实际账号确认。
- 仅有告警通知不保证存在可导出的录像，全天录像也不保证提供事件索引。
- SD 历史回放可能依赖摄像机在线；已经覆盖或损坏的录像不可通过本项目恢复。
- 保存回放不保证快于实时播放，需要测量可用速度和每日待办总时长。
- LaunchAgent 需要用户登录会话；重启后未登录和主机休眠期间不能保证按时执行。

## MVP 发布门槛

必须先通过“真实 C6C 的 60 秒历史片段导出”。之后完成一天真实事件的端到端备份、重复运行不产生副本、至少一次下载与上传中断恢复、远端独立核验、Mac 资源记录和连续三天定时运行。

发布说明必须列出测试过的 C6C 固件、Mac 架构、macOS、Python、FFmpeg 与 aliyunpan 版本，并区分代码测试结果和实机测试结果。
