# 开发路线

优先验证最不确定的设备能力，再实现自动化。各阶段以验收结果推进，不用日期承诺替代实测。

| 阶段 | 交付 | 完成条件 | 当前状态 |
| --- | --- | --- | --- |
| P0 文档与仓库 | 需求、架构、接入边界、配置与调度模板、社区文件、CI | 本地及 GitHub 仓库检查通过 | 本次建设范围 |
| P1 能力探测 | 最小 `probe`、安全凭据读取、合成接口测试 | 真实 C6C 指定历史60秒可保存，事件索引可用；固定外部工具版本 | 未实现、未实测 |
| P2 手动备份 | 单次 `run`、SQLite、单片串行、上传及远端核验、`status` | 一天真实事件完成；重复运行幂等；两类中断可恢复 | 未开始 |
| P3 Mac 自动化 | launchd 安装/卸载、日志轮转、预算及补漏 | 连续三天定时运行，锁屏与休眠行为记录，资源达到目标或披露偏差 | 未开始 |
| P4 MVP 发布 | 完整部署说明、兼容性矩阵、版本和变更记录 | 所有 [MVP 发布门槛](requirements.md#mvp-发布门槛) 通过，标明限制 | 未开始 |

## P1 分支决策

- 标准 HTTPS 历史流可保存且事件索引可用：沿现有设计实现。
- 索引不支持、权限或服务条件不满足：报告阻塞和已核实证据，保持“能力待验证”状态，不铺开自动化实现。
- 只有 ezopen 或加密不兼容：先调查合法 SDK 的 macOS 架构支持、许可证与成本，另写 ADR；不默认引入 VM、关闭加密或改成直播录制。
- 上传工具无法提供稳定的远端元数据：保留适配器边界，评审可授权的元数据获取方式；不能直接省略核验。

## 暂不纳入

多摄像机、菜单栏或网页界面、推送通知、人物识别、视频剪辑合成、实时 RTSP 录制、云端生命周期管理都在 MVP 之后评估。只有真实需求和资源测量支持时再增加后台服务或大型依赖。

本地安全清理在显式实现、测试和开启前保持禁用；默认暂存填满会暂停，详见 [运维设计](operations.md)。
