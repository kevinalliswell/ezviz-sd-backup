# ADR 0002：先验证历史事件导出能力

- 日期：2026-11-01
- 状态：设计已采纳，设备能力待验证

## 背景

萤石官方列出本地录像检索和回放接口，但个人账号权限、C6C 固件、事件索引、加密和 macOS 标准媒体保存的组合尚未实测。App 可回放和设备可输出实时 RTSP 都不能证明这一链路成立。

## 决策

以“真实事件索引 + 目标 Mac 保存指定历史60秒”作为实现自动化之前的门槛。标准 HTTPS HTTP-FLV 是首选验证路径，FFmpeg 通过 stdin 接收媒体，不暴露签名地址。保持用户已有加密设置。

能力不满足时报告明确阻塞，不宣称兼容 C6C。只支持专有协议时，SDK 必须另外核实 Mac 架构、许可证及维护成本，形成新决策后再实现。

## 替代方案

持续录制直播会改变用户需求、增加资源与存储消耗，当前不采用。模拟私有 App 接口、要求关闭视频加密或以 Windows/Linux SDK 推断 Mac 可用，都不作为默认方案。

## 代价与验证

项目可能在探测阶段被设备或账号条件阻塞；这比继续构建无法接入真实录像的自动化更早暴露问题。探测需用户合法授权和目标硬件。所有官方参数及已知限制见 [萤石接入](../integrations/ezviz.md)，不能用本文替代最新官方文档。
