# 运维与故障恢复设计

以下行为均为待实现契约。当前仓库检查通过不代表这些运行行为已经存在。

## 发现范围与补漏

默认每次查询最近三个**完整自然日**，按 `backup.timezone` 解释。例如 11 月 1 日 03:15 执行时，查询 10 月 29、30、31 日，不扫描当日尚未闭合的录像。跨日片段仍按确定的边界拆分并记录来源。

发现结果幂等入库，再处理所有已知未完成任务，最旧优先；已知任务不受三天发现窗口限制。平台分页必须读完才能确认发现完整。空结果、接口失败、无进展游标分别记账。

默认窗口无法发现停机超过三天期间的全部事件。未来手动日期回补入口应接受明确起止日期，仍按日分页并受同样预算控制；日期范围不能超出实际可读的 SD 保留期。已经循环覆盖的录像记录为不可恢复缺口，需要用户查看，不能计为成功。

## 预算与积压

每次任务最多运行 10800 秒，单个媒体片段最多 1800 秒，下载与上传并发均为 1。分段只改变处理粒度，保留完整事件时间范围。外部子进程的等待时间也计入全局预算；收尾应在预算内终止子进程并持久化状态，不能只在片段之间检查时间。

暂存目录内所有原片、失败 partial 和已核验文件都计入 2 GiB 上限；写入期间持续检查至少 5 GiB 的磁盘空闲要求。预计大小未知时也不能无限接收；达到上限中止当前写入、保留可恢复记录并退出 6。

**默认关闭本地清理，因此暂存空间最终可能填满，备份会暂停。** 这是一项保护原片的保守默认值，不适合在无人管理的情况下无限运行。状态摘要应显示当前占用、最旧待办、核验等级和暂停原因。用户在核对远端后可手动移走已核验原片；自动清理必须另行显式开启并满足下文条件。

若历史回放仅能按接近实时的速度保存，每日事件总时长可能超过三小时。实测应比较每日新增量与实际处理能力；不能通过静默丢片、截断事件或偷偷提高并发来掩盖积压。

## 重试分类

| 情况 | 行为 |
| --- | --- |
| 临时网络失败、服务端繁忙 | 最多三次网络尝试，指数退避及抖动；受总预算约束 |
| 限流 | 尊重可用的服务端等待提示；预算不足留到下次 |
| 访问令牌过期 | 有限刷新一次后重新请求；仍失败则退出 3 |
| 凭据无效、需要扫码、权限拒绝 | 不反复登录，记录需要用户操作，退出 3 |
| 设备或协议不支持、无事件索引 | 报告具体能力缺口，退出 4 |
| 远端空间不足、媒体截断、冲突 | 保留原片和错误状态，退出 5 |
| 运行或磁盘预算耗尽 | 保留待办及进度，退出 6 |

失败片段记录下一次可重试时间，不能阻止同一运行中其他可处理片段，也不能在一个坏片段上无限循环。授权或系统性能力故障则提前结束本次运行。

## 中断后的处理

- 保存中断：partial 不算有效视频；重跑前按策略删除或隔离该未完成文件，重新保存，不直接追加未知媒体数据。
- 本地文件已完成：复查路径、大小、媒体及哈希后复用；不重复下载。
- 上传中断：先查询固定远端路径；确认内容一致则复用，否则按工具已验证的续传语义重试；遇到冲突不覆盖。
- 上传成功但元数据暂不可用：保留 `UPLOADED`，下次独立核验，不能重复计为完整备份。
- 已核验文件本地被用户移走：保留远端记录；需要重新上传时先确认远端状态，不将本地缺失转换为云端删除。

SIGTERM 和 KeyboardInterrupt 都应触发有界收尾。强制杀进程或断电后，SQLite 事务、文件原子提交与下次状态检查共同恢复；不要依赖退出钩子一定执行。

## 清理与数据保护

应用不删除 SD 卡录像，不传播本地删除到云端，不自动删除远端对象。

本地清理默认 `enabled=false`。未来开启后，只有远端路径、精确大小及 SHA-1 一致且本地原片保留满 `keep_days` 的记录才可清理。只匹配大小、核验过期或失败、上传中、冲突记录均不可清理。清理先提供预览，再删除精确文件；不得递归清空数据目录。

数据库或配置损坏时先停止调度并保留副本，不在启动时静默重建为空库。迁移前备份 SQLite；恢复旧副本后对照远端对象，仍遵循“不覆盖、不删除、先核验”。不要把数据库备份、日志或录像提交到仓库。

## 运行摘要

未来 `status` 和每次运行结束应提供：运行结果、发现日期、发现数量、完成及各核验等级数量、待办数量、最旧待办时间、失败类别、暂存字节数、耗时和退出码。部分失败不能显示为整体成功；一个日期处理完成也不证明此前所有日期都已备份。

只输出摄像机别名和脱敏片段标识。不打印序列号、Keychain 内容、完整请求响应、签名回放 URL、账号标识或网盘令牌。应用日志和 launchd 输出文件合计需要有界保留；公开排障只分享审阅后的摘要。
