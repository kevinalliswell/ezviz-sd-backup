# 萤石 SD 历史录像接入

## 已知事实与验证边界

目标是用户现有 C6C 的 SD 历史告警录像。官方 API 文档说明平台具有本地录像检索及回放能力，但没有在本文中承诺所有 C6C 硬件、固件和个人账号都能使用。

本地 RTSP 实时流不能证明 SD 历史录像可导出；App 能回放也不能证明第三方开放平台拥有相同权限。不要将两者作为能力验证通过的替代证据。

## 接口映射

以下内容按 2026-11-01 查阅的官方文档记录，开发时重新确认。这里只使用公开接口，不模拟 App 私有登录、不逆向账号接口。

| 用途 | 方法与路径 | 关键字段及单位 | 来源 |
| --- | --- | --- | --- |
| 本地录像统一查询 | `GET /api/v3/device/local/video/unify/query` | Header: `accessToken`、`deviceSerial`、`localIndex`；Query: `recordType=2` 表示事件录像，`startTime` / `endTime` 为秒级时间戳 | [官方文档](https://open.ys7.com/help/3922) |
| 兼容的录像查询路径 | `POST /api/lapp/video/by/time` | `recType=2` 表示本地录像；`startTime` / `endTime` 为毫秒时间戳；分页需 `version=2.0`、`pageSize` | [官方文档](https://open.ys7.com/help/1422) |
| 获取历史回放地址 | `POST /api/lapp/v2/live/address/get` | `type=2` 表示本地回放；`protocol=4` 表示 FLV；`startTime` / `stopTime` 使用 `YYYY-MM-DD HH:mm:ss` | [官方文档](https://open.ys7.com/help/1414) |

注意 `recordType`、`recType` 和 `type` 属于不同接口，数值含义不能互换。新版查询的 `recordType=2` 是事件类型；旧版的 `recType=2` 是 SD 来源，并不自动完成告警筛选。

标准回放协议及 H.264/H.265 的具体可用组合需要用目标摄像机验证。文档中存在一个 `downloadPath` 字段，但官方明确说明它不可用于直接下载录像。

## 授权前提

用户在萤石开放平台确认开发者资格、应用和设备授权，取得合法的 API 凭据；具体流程及个人账号可用范围以当时控制台为准。不要为了实验删除、转移或重新绑定已有摄像机。

应用只需要查询及回放相关权限，不应索取配置摄像机、删除录像或管理其他设备的权限。AppKey、AppSecret、访问令牌与可能需要的视频验证码只保存在目标 Mac 本地；凭据存储见 [配置约定](../configuration.md)。

访问令牌有到期时间。适配器应缓存到用户数据目录、提前有限刷新，并在平台返回到期错误时最多重新获取一次后重试；权限拒绝不能被无限刷新掩盖。平台费用、并发限制、流量额度及标准回放服务开通条件需在使用者账号确认。

## 检索与分页

1. 将待查询日期按 `backup.timezone` 拆成自然日；内部使用左闭右开区间。
2. 优先使用新版接口查询事件录像，第一页结果立即归一化并写入 SQLite。
3. `hasMore` / `nextFileTime` 驱动翻页，边界重复通过稳定键去重；游标无进展时报告分页异常并停止该日。
4. 旧接口只在明确的“不支持当前接口”能力错误下作为兼容路径，不能在授权失败或空结果时自动切换。
5. 旧接口需要核对返回的 `localType` 是否为事件；如果只有定时录像且没有可验证的告警时间来源，报告 `EVENT_INDEX_UNAVAILABLE`，不上传全天录像。
6. 没有录像与查询失败必须区分；无法确认查询完整性时不能把该日标记为完成。

跨午夜事件按录像可用范围拆分。默认保留平台给出的原始事件范围，不额外假设存在告警前的视频；最大分段时长只用于切分，不能丢弃超出的部分。

## 保存标准回放流

MVP 的首选探测路径为 FLV 回放地址。只有实际返回可读取的 HTTPS HTTP-FLV，且编码可被 FFmpeg 流复制为 MP4 时，才进入这一实现路径。

Python 以标准库 HTTPS 客户端分块读取，向 FFmpeg stdin 写入，避免签名 URL 出现在进程参数里。流缓冲上限、阻塞写超时、服务器提前断开、FFmpeg 提前结束与 SIGTERM 都需要测试。HTTP 200 也可能包含错误页，必须验证媒体而不能只看 HTTP 状态。

保存结束后用 `ffprobe` 检查至少一个视频流、实际时长、可读性和非零大小，并对首尾画面做实机抽查。允许的时长偏差需要根据设备关键帧和回放行为测量后制定；明显截断的文件不能进入上传队列。

如果只有 `ezopen`、加密流无法处理、或无法在资源预算内保存，则记录 `PLAYBACK_EXPORT_UNSUPPORTED`。SDK 路径需要单独确认目标 Mac 架构、维护情况及许可证后再设计，不能将 Windows/Linux SDK 兼容性当成 macOS 支持。

## 首次实机验证

| 步骤 | 必须取得的证据 |
| --- | --- |
| 记录环境 | C6C 完整型号/固件、Mac 架构、macOS；序列号留在本地 |
| 确认权限 | 合法账号能查询该设备，权限和费用已由用户确认 |
| 检索已知事件 | App 中的事件时间与 API 返回能够对照 |
| 保存历史 60 秒 | 得到可播放文件，画面属于指定历史时段而非当前直播 |
| 验证媒体 | 视频、声音、时长、编码及大小符合预期 |
| 记录成本 | 实际保存耗时、CPU/RSS、是否经过云服务及流量消耗 |

未完成以上门槛前，仓库状态应继续标记为“设备能力待验证”。历史录像已经被 SD 卡覆盖时，记录为不可恢复缺口，不能静默跳过或声称已备份。
